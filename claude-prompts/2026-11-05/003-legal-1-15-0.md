# Privacy policy for app 1.15.0 (second try — texts corrected from report 002): Help improve Daili (usage counts + crash reports), one-question surveys, Tips & suggestions, Edit in Daili, share → event, AI for adults

## Why
Prompt `002-legal-1-15-0` stopped (report `claude-reports/2026-11-05/003-legal-1-15-0.md`) because several
sentences did not match the code. Every sentence below was rewritten against that report's findings 1–11.
Read the report first; then check again — the same rule holds: a sentence that is not true → stop and report.

App 1.15.0 (21) and the server behind it changed things the privacy policy must say. It must be true and
**deployed before build 21 goes into review**:

1. **Help improve Daili** (api `32ce92e`, app `8d3a0696` + `d2973162`): an opt-in switch (last sign-up
   screen, a one-time Home sheet for existing parents, Settings → About under Privacy policy). ON = the app
   counts per day which screens it opens and which of a few "moments" are reached (numbers only, keys like
   `screen.calendar`; nothing while a Cycle page is open) and sends finished days once a day to
   `POST /v1/usage` (`usage_counts`, 400 days, deleted when switched OFF, exported, anonymised on account
   deletion) — AND the app sends crash reports to Firebase Crashlytics (Google): stack trace, device model,
   OS + app version, time; no user id, no custom keys, no logs (`crash_reporting_guard_test`); OFF = unsent
   reports on the phone are deleted. Only adults may say yes (`USAGE_SHARING_ADULTS_ONLY`: admin of the active
   family, or `adult_confirmed_at`). The web counts nothing.
2. **One-question surveys** (api `32ce92e`, app `2026-11-02/006`): `survey_due` → a one-time Home card
   (skippable); the answer + optional note + app version + family go to `POST /v1/survey-answers`
   (`survey_answers`); on account deletion user id and note are nulled.
3. **Tips & suggestions** (api `8821ca8` `cc7149a` `272da7b`, app `fd1d9d2e`, web `e3afb43`): `users.notify_tips`
   (default ON, switch in Settings → Notifications, app + web); server `nudges:dispatch` picks at most one tip
   per person per day, early evening local, never in quiet hours, from facts the server already holds (days
   since sign-up, last use, which features the family uses, waiting invites, devices); stores `user_nudges`
   (which tip, when, opened or not — `POST /v1/nudges/opened`); 10 % random hold-out for 8 weeks; switch +
   history in the data export. Sending is OFF until Ammar switches it on after the release.
4. **Edit in Daili** (api `82718cc` `44a6466` `a67311c` `16dc288`, app `fe8a3475`, web `ee5bfb4`): "Copy to
   Daili" became "Edit in Daili". The saved Daili event keeps a reference to the original (`events.source_*`:
   subscription id + stable key + a snapshot of time/title/place); the original is hidden in Daili while the
   link exists (index, wall screens, digest, MCP agenda, TRMNL); the hourly/on-demand refresh carries time,
   title and place changes of the ORIGINAL into the Daili event (fields the person changed themselves →
   the app asks "Use it / Keep mine"; original gone → "Removed from … → Delete / Keep"); linked events can't
   repeat; copies made before 1.15.0 were linked once (`calendar:link-copies`). Phone-calendar copies: hidden
   on that phone only, never auto-updated. Data export carries the 6 new fields.
5. **Share a message → Event** (api `7f7ea37`, app `342d0a85`): the shared text or screenshot is sent to
   Gemini once to suggest an event (1 AI action); nothing stored until Save.
6. **AI for adults** (api `8c5dc75` 2026-11-02/007, app `2026-11-02/007`): every Gemini feature needs an
   adult — `users.adult_confirmed_at` OR admin of the active family; the app asks once "Are you 18 or older?".
7. **Calendar links "Only me"** (api `cf0288d`): a member may add an .ics link only they see.
8. **Refresh now** (api `8b6333d`): on request, at most every 5 min — no new data, no text needed.
