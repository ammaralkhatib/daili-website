## The facts to cover (commit refs = where to check)
1. **Habit rewards** (api `bb59be59` `0a3f6423` `63b8624b`, contract `claude-prompts/HABITS-3-PLAN.md` §5 in the
   api repo): a reward (title, icon, colour, for whom, stars needed, which habits count, starts again, rounds,
   who tapped "We did it" and when) is stored on our server and **visible to everyone in the family**. Stars
   are counted from the existing habit ticks; **private habits earn no stars**. When a reward is reached, family
   members get a push (habit notifications switch) and one activity-feed row. In the data export; deleted with
   the person's rewards when they leave, and with the family. Minzi / energy / trips: if the policy mentions
   them, say they ended (old data is kept for a while for old app versions, then deleted — check how D2 is
   implemented; if no delete job exists yet, say "kept until we delete it in a later update" honestly, or leave
   the old wording and list it in the report).
2. **Stock lists** (api `13e3bff5` `7a67dbd0`): a third list type; we store when an item was marked low/out and
   by whom; marking it out adds it to a shopping list.
3. **Saved copies on the phone + offline sending** (app `b85e46ab` `c25f8363` `2504e9c6` `09656b81`, api
   `b2315c79` `2cd539cc`): notes and lists are kept as a copy **on the phone** so they open offline; it is
   deleted at sign-out. Adds/ticks made offline wait on the phone and are sent later; each carries a random
   `client_id` stored with the item (only its creator sees it) so it is never saved twice.
4. **Read aloud** (app `b733add6` `f6de86a5` `fdaa801e`, plugin `packages/daili_speech`): the phone's OWN voice
   reads; **nothing is sent to us or to any cloud voice service**. Android "Speak my reminders" also runs only
   on the phone. If "Help improve Daili" is ON, the usage counts include `read_aloud.*` counts (numbers only;
   api `a2e3c3c9`) — add it to the existing Help-improve paragraph only if that paragraph lists count keys.
5. **Meal wishes** (api `7874dce7` `4cddfaa2`): a wish (the meal, who wished it, for whom) is stored and seen
   by the family; the wisher gets a push when it is planned (own switch "Your meal wishes"). "Who's eating"
   (api `04a5012`): we store who is NOT eating a planned meal.
6. **Personal event reminders** (api `7032ece`): each person's own reminder choice per event is stored.
7. **Recipes from Instagram** (api `3520ec37`, app `f2353953` `f9c13c4c`; CLAUDE.md §3 "AI is adults-only +
   Meals 2.0"): the PHONE opens the public Instagram post once (no login, no cookies), takes only the post's
   caption text and sends it to our server, which sends it to Google Gemini to read a recipe (1 AI action,
   adults only). Our server never contacts Instagram. The username and likes are never sent. The post's picture
   is downloaded by the phone (metadata removed) and uploaded to us **only if the user keeps it and saves** the
   recipe. A remote off-switch exists. Facebook/TikTok: not read.
8. **Several photos → one recipe** (api `e0568f0d`): up to 5 pictures are sent together to Gemini (update the
   existing photo-reading sentence if it says "a photo").
9. **Shift roster from a photo** (api `0fcbd24`): the photo plus the NAME the user typed go to Gemini so only
   that person's shifts are read; up to two months.
10. **Notes of synced calendar events** (api `86ac6cc1`): for Google, Outlook and .ics calendars we now also
    store each event's **description** (cleaned to plain text, max 2,000 characters). Check the policy's Google
    / Microsoft calendar section and its Google "Limited Use" wording still fit (the description is shown only
    to the family that connected it; never sent to AI apps via the MCP connector — check
    `tests/Architecture/McpNoPrivateAreasTest` / the MCP rule) and add the description to the list of stored
    fields.
11. **Fix (from Ammar's 2026-11-08 safety round):** the policy says somewhere that "every request is signed in"
    (or similar, in §6 / security). Find it; make it true (public pages, the invite landing page, webhooks and
    the newsletter form are not signed in) — say what IS protected instead.
12. **Note link previews** (old, `LinkPreviewFetcher` + `NoteLinkImageCopier`, CLAUDE.md §3: the server loads a
    link a family saves in a NOTE to show a preview, Instagram included): check the policy already says this. If
    not, add one honest sentence.

Not new data (no text needed unless the policy contradicts it): budget weekend shift, "More days", the UX
